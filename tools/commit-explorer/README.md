# 提交放映室

在仓库根目录执行 `npm run explorer`，打开 http://127.0.0.1:3210。
需要 Node.js 22+、Git、tar 和 npm。默认仅本机可访问，可用环境变量 `EXPLORER_PORT` 更换端口。

- 从本仓库 `git log --all --topo-order` 读取最近 180 个提交；默认展示到教学基线，勾选“显示更早历史”可展开。刷新读取本地引用，需要远端新提交时先自行 `git fetch origin --prune`。
- 连线来自提交的父 SHA，合并提交有多条连线；分支标签是当前 Git 引用，已删除分支仍可沿合并历史查看。图中颜色用于区分图形轨道，角色名称以提交说明为准。
- 点击最多三个节点并排运行历史游戏，独立窗口适合投影全屏。窗口较窄时自动上下排列。
- 游戏展示区固定为 16:9；内部游戏以至少 1280×720 的视口等比缩放，单栏和多栏均保持相同比例。
- 通过 `git archive` 提取准确提交，按该提交的 package-lock 安装依赖（禁用安装脚本），再运行该版本的 Vite 构建。历史代码在本机执行，仅用于自己信任的本仓库。
- 快照和构建缓存位于忽略目录 `.commit-explorer/`，不会切换成员仓库分支，也不包含未提交文件。相同 lockfile 复用依赖，构建串行执行，失败显示原因并可重试。首次依赖安装需要网络。
- 历史游戏的 localStorage 在同源页面间共享，因此最高纪录等本地存储可能相互影响；运行中的游戏场景各自独立。面板不是自动化测试或独立存档环境。
- 停止服务：终端按 Ctrl+C。缓存可在服务停止后手动删除。

建议演示顺序：`6bd5f13` 教学基线 → `ab2373a` 玩法 / `1376cf2` 美术 / `a44071d` 界面 → `de0c1bc` 合并成果 → `08aeeba` 模块重构。
