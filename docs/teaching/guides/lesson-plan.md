# 45 分钟课堂操作脚本

## 备课

三个 clone 打开三个 Rider 窗口，以文件夹名和分支识别角色。origin 指向教师公开仓库，upstream 指向原项目，Push 仅选 origin。每个副本 npm ci；A/B/C 端口 3101/3102/3103。

共同基线是 classroom-start。当前角色分支只有任务说明，课堂功能需要按 tasks.md 先制作和预演；不要提前合并掉课堂要展示的 PR。

每个角色准备小提交、验收截图和可恢复的提交 SHA；备好冲突录像。完成后在已验收的集成提交创建 classroom-finished。不使用强推覆盖课堂历史，下一轮演示使用新教学分支或新仓库。

## 时间安排

| 时间       | 操作                                         | 教学目标                     |
| ---------- | -------------------------------------------- | ---------------------------- |
| 0–5 分钟   | 玩基线，展示共同目标                         | 团队交付同一个游戏           |
| 5–10 分钟  | 三个 Issue / 角色任务 / 接口约定             | 分工还需要约定交接           |
| 10–18 分钟 | A 在 Rider 改参数、Diff、Commit、Push        | 工作区、提交、远端是不同状态 |
| 18–25 分钟 | B/C 展示准备好的差异，建立角色 PR            | 同一起点可独立开发           |
| 25–30 分钟 | 合并 A；C Fetch、合入 main、解决按钮文案冲突 | 理解双方意图后解决文本冲突   |
| 30–37 分钟 | 展示计分选择器故障，修复 PR                  | 无文本冲突也可能有功能错误   |
| 37–41 分钟 | 集成美术、UI 与玩法，运行验收                | CI 与游戏交互验收互补        |
| 41–45 分钟 | Rider Git Log 查看图，布置小组任务           | 每人账号、每项任务一个 PR    |

## Rider 操作提示

1. 打开正确角色目录，核对顶部当前分支。
2. 修改后在 Commit 面板看 Diff，只选本任务文件；写具体提交说明。
3. Push 到 origin 的同名功能分支。
4. GitHub 创建 PR，base=main，compare=角色分支；用角色前缀和标签。
5. 合并他人 PR 后，另一工作区执行 Fetch；Fetch 只更新远端引用，不自动修改工作文件。
6. 在当前功能分支合入 origin/main；有冲突时用 Rider 三方合并视图理解 base / 两边改动，检查结果再提交。
7. 再次 Push 更新原 PR，运行检查和游戏；最终 main 拉取后验收。

## 验收与课堂恢复

至少验证：开始、两档难度、两个方向落块、计分、失败、重开、裁切与掉落、窗口变化、UI 点击不误触。当前未实施角色功能，所以此清单是未来验收要求。

不要用 Reset/force-push 演示公共回滚。撤销公共错误用新修复提交或 Revert；PR merge commit 的 Revert 应明确主线 parent，初学课堂优先展示 GitHub 的 Revert PR（若可用）。失败时用另一个目录打开 classroom-start，不删除学生或教师的未提交修改。
