# 三角色协作边界

| 角色                           | 独立修改范围                                              | 验证入口                        |
| ------------------------------ | --------------------------------------------------------- | ------------------------------- |
| A 玩法                         | src/gameplay、**tests**/gameplay                          | Node 环境玩法测试，不需要 WebGL |
| B 美术                         | src/presentation、src/dev/art-lab、**tests**/presentation | /art-lab.html、场景测试         |
| C UI                           | src/ui、src/dev/ui-lab、**tests**/ui                      | /ui-lab.html、界面测试          |
| 集成负责人（可由三人之一兼任） | src/app、src/runtime、src/storage、构建配置、集成测试     | 完整游戏流程                    |

contracts 的修改需要受影响角色共同评审。A 不修改 Mesh/Body/DOM；B 不改计分、概率或碰撞尺寸规则；C 不直接改玩法状态。新增功能若跨界，先提交契约和样例，避免双方各自猜字段。

## 工作区与分支

member-a-gameplay、member-b-art、member-c-ui 是同一远端仓库的三个完整 clone，不是三个相互依赖的源码目录。当前重构仅发生在 A 工作区的 codex/refactor-module-boundaries，未合并 main，也未切换 B/C 工作区。

重构阶段不在角色分支同时修改旧公共大文件。需要并行时，可独立准备纯规则测试、美术样例与 UI 快照，由集成负责人连接。

后续批准合并之后，各自 fetch 并将最新 main 合入角色分支；不要复制文件夹覆盖其他工作区。故障演示分支保留历史教学用途。

## 提交和验收

搬迁与逻辑调整分阶段提交；不夹带全仓库格式化。PR 使用中文说明问题、模块边界、检查结果和浏览器证据。合并 main 需要用户明确授权。

每个阶段运行 lint、三个项目类型检查、相关测试及构建；跨模块阶段运行全套测试。最终检查难度、裁切、奖励、救援、纪录、重开、窗口尺寸与资源释放。

历史角色任务和冲突演示见 [归档任务](../teaching/archive/tasks.md)，其中旧路径仅适用于历史提交。
