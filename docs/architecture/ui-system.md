# UI 系统与内容规范

适用于第一轮反馈信息优化。UI 仅消费 `GameSnapshot`，通过 `GameCommands` 发出操作；不读取 Three 对象、玩法内部状态或存储，不改变碰撞、计分、奖励概率与暂停规则。

## 结构与职责

| 位置                                   | 职责                                                |
| -------------------------------------- | --------------------------------------------------- |
| `src/ui/GameScreen.ts`                 | 组合根：创建组件、分发快照、阶段切换焦点、统一销毁  |
| `src/ui/components/Hud.ts`             | 层数/得分主次、纪录、护盾槽、持续能力、五格奖励进度 |
| `src/ui/components/RewardDialog.ts`    | 奖励选择、稳定卡片身份、焦点循环、命令转发          |
| `src/ui/components/RunMenu.ts`         | 开始和结算布局、下一局难度、保留上一局结算信息      |
| `src/ui/components/Feedback.ts`        | 根据快照变化触发短反馈，管理并清理定时器            |
| `src/ui/components/primitives.ts`      | 小型共享约定：View 生命周期、文本更新、等级点       |
| `src/ui/rewards/catalog.ts`            | 奖励名称和精确规则说明                              |
| `src/ui/rewards/presentation.ts`       | RewardId 到图形、色彩、类别、短说明、展示等级的映射 |
| `src/ui/assets/icons.ts`               | 原创 24×24 单色 SVG 图标                            |
| `src/ui/assets/rewardIllustrations.ts` | 原创 160×100 奖励效果示意图                         |
| `src/ui/styles/tokens.css`             | UI 颜色、间距语义、圆角与基础动效时长               |
| `src/ui/styles/{hud,rewards,menu}.css` | 按功能划分的组件样式                                |
| `src/dev/ui-lab/fixtures.ts`           | 独立、确定性的视觉验收样例                          |

保持四个功能组件，不引入通用状态库、事件总线、模板引擎或动态插件注册。只有出现第二个实际使用场景才提取共享组件。`View<T>` 约定 `element / update / dispose`，组件自行清理持有的监听和计时器；组合根的销毁是幂等的。

## 数据语义

- 层数是主指标，得分保留为次级指标；不修改实际得分与纪录规则。
- 护盾槽只读取 `shields`；`rewards.shield` 是历史获得次数，不能充当剩余数量。
- `repair` 是即时效果，不作为常驻能力显示；持续能力仅列已获得项。
- 奖励候选以 `rewardChoices` 为准，UI 不自行抽取、过滤或计算资格。
- 当前五格进度和 2/3 等级上限是既有公开规则的展示映射，不是玩法计算。如果玩法调整这些规则，需同步审查这里及样例；未来可通过契约公开上限。UI 不导入 gameplay 常量。
- 奖励示意图表达概念，不声称是实时尺寸预览。当前快照没有塔顶尺寸，不展示虚构的修复百分比或精确前后图。
- 在进入 ended 时保留本局展示快照。随后切换难度仅配置下一局，不能重写上一局的难度和纪录说明；新一局清除缓存。
- 瞬时提示依据层数、救援次数、阶段变化触发；重复快照不能重播或延长提示。连续连击没有额外分数倍率承诺。

## 资源与内容管理

1. 稳定 ID 使用 contracts 的 `RewardId`，禁止用中文标题作为逻辑键。
2. 新增奖励内容先补 catalog 和 presentation，再补图标/示意图、UI fixture 与相应测试。文案和参数说明只在 catalog 维护，组件不复制完整规则。
3. 图标统一 24×24、currentColor、无内嵌脚本/外链；效果图统一 160×100。SVG 以受版本控制的静态 TS 字符串存储，避免加载链和测试环境对 SVG 导入的分歧。不得向这些字符串插入用户输入。
4. 当前所有图形均为本项目原创程序化向量，无第三方素材或网络字体依赖。未来栅格素材放 `src/ui/assets/images/`，新增时登记来源、许可、用途及分辨率；禁止散落在组件目录或使用热链。
5. mint 表示修复、blue 表示节奏/保护、gold 表示精准/稳固。类别同时有文字和形状，不能仅靠颜色传达。
6. 不为尚不存在的装备位、稀有度、升级价格或奖励机制添加视觉暗示。效果参数变更必须与玩法维护者核对，不靠 UI 推算。

## 交互与验收

### 1920×1080 字体规范（第二轮）

按 1920×1080 CSS 视口、浏览器 100% 缩放验收，不用整体缩放 transform 缩小 UI。主字体优先 Microsoft YaHei，随后 PingFang SC / Noto Sans CJK SC / Segoe UI 和系统无衬线；不下载远程字体。中英文共用层级，数字使用 tabular-nums。正文常规字重，标题 600，避免细体承载小字。

| Token               | 目标字号 | 用途                                                 |
| ------------------- | -------- | ---------------------------------------------------- |
| `--text-small`      | 18px     | 辅助说明、资源名称、进度、按钮次级提示，玩家文字下限 |
| `--text-body`       | 20px     | 奖励规则、难度、面板说明                             |
| `--text-emphasis`   | 24px     | 主要操作、即时正反馈、结算次级数字                   |
| `--text-card-title` | 30px     | 奖励名称                                             |
| HUD 次级数字        | 40px     | 得分，与主层数拉开层级                               |
| `--text-title`      | 48px     | 页面和奖励标题                                       |
| `--text-hero`       | 112px    | 层数与结算成绩                                       |

正文行高 1.6–1.65，标题 1.15，大数字 1.05–1.1。不得在功能样式中新增 10–14px 玩家文字。700px 以下是单独响应式档，辅助文字最低 16px，正文 18px；布局应滚动/换行，而不是继续缩小字号。

菜单与奖励采用暖纸底、苔绿正文；游玩 HUD 保留深色衬底，避免浅色移动方块从字后经过时损失对比度。基础色对计算：辅助文字 #52685f / 最深纸底 #d6e4d9 约 4.55:1，正文 #263e38 / #e6eee0 约 9.66:1，HUD 辅助文字 #d0dfd7 / #203a3a 约 8.81:1；透明合成和所有动态画面仍以视觉检查为准。不要用整体 opacity 降低正文对比度。

### 动效与正反馈规范

`feedbackModel.ts` 是无 DOM 的反馈选择策略；`motion.ts` 是组件拥有的可中断动效工具。优先级为救援、奖励获得、首次突破已有纪录、连击、普通落块。相同快照不重播；破纪录提示只在首次跨越时出现，不能每层重复。奖励暂停时的第五层成功由奖励页文案承接。

- 背景情绪：菜单塔形 5 秒轻浮动，不晃动整个画面。
- 操作响应：落块时层数、得分、进度 380ms 回弹；连击和资源变化 540ms 强调。
- 奖励：卡片 650ms 分序入场（间隔 90ms），悬停插图轻浮动；选择立即生效，无人为等待或额外落块。
- 正反馈：普通/完美 1 秒、连击 1.4 秒、获得/救援 1.8 秒、纪录 1.9 秒；完美以上加入有限叶片飘散，普通落块不喷洒装饰粒子。
- 结算：成绩柔和展开，新纪录徽章有限次数发光。
- 组件销毁清理计时器和 Web Animations；同一元素新动画取消旧动画。reduced-motion 同时关闭 CSS 和脚本动画，数值与文字结果保留。
- UI 实验页新增“完美反馈 / 连击反馈 / 纪录反馈”按钮，直接复现反馈，不改变完整游戏的状态或规则。

控件携带 `data-game-control`，防止点击卡片或菜单同时落块。奖励弹窗支持 Tab/Shift+Tab 循环，一项奖励也能操作；相同快照不重建卡片或抢走焦点。退出奖励后焦点回到 canvas，结算首次出现才聚焦再玩。装饰 SVG 隐藏于辅助技术；数值、资源和进度有可访问名称。遵循 reduced-motion，仅保留结果，不强制播放 UI 动画。

- `/`：完整游戏。检查开始、难度、落块、奖励、救援、失败、重开。
- `/ui-lab.html`：七种 UI 快照，包含满级加成、三类奖励和单项奖励；这是视觉样例，不是玩法证明。
- `/integration-lab.html`：现有开发用固定落点夹具，真实规则和渲染；检查五层奖励、卡片点击不额外落块、护盾消耗、结算。
- 桌面、390px 手机宽度、窄短窗口检查遮挡/滚动/溢出；含 320px 宽度边界。
- 运行 lint、三个项目的 type-check、全套 Jest、生产 build。

本轮不修改 3D 特效、音效或帧循环。奖励暂停时的场景动效、修复尺寸动画属于后续跨模块工作。
